# 사용자 행동 로그와 어드민

로컬 앱: http://127.0.0.1:5174/alarms
로컬 어드민: http://127.0.0.1:5174/admin.html

로컬 개발 서버는 `/__ubl/events`로 받은 이벤트를 메모리에 보관합니다. 테스트 데이터를 생성하지 않고 실제 브라우저에서 누른 행동만 표시합니다. 재시작하면 초기화되며 운영 서버에 전송하지 않습니다. 같은 로컬 주소를 사용해야 합니다(localhost와 127.0.0.1은 서로 다른 브라우저 저장소).

운영 어드민은 서버의 `/admin.html`입니다. 기존 `/dashboard.html`에도 새 UBL 화면 링크가 있습니다. API 조회는 `DASHBOARD_SECRET`을 Basic 인증 헤더로 전달해야 하며 URL 쿼리나 코드에 비밀번호를 넣지 않습니다. 서버 환경변수가 없으면 503을 반환합니다. 비밀번호는 화면 메모리에만 유지합니다. 운영에서는 HTTPS를 사용합니다.

## 배포

1. 서버에 `DASHBOARD_SECRET`을 설정하고 변경한 서버 코드를 배포합니다. 기존 인증·로그인 수정과 `ALLOW_LEGACY_API`는 변경하지 않습니다.
2. 신규 행동 이벤트가 포함된 앱 빌드를 업로드하고 검토·출시합니다. 기존 앱 이벤트도 수집하되 신규 로그인 퍼널은 새 빌드부터 완성됩니다.
3. 운영 어드민에서 로그인→알람 등록 이벤트를 확인합니다. DB 스키마 변경은 없습니다.

## 집계

- 탭별 sessionStorage 세션 ID는 비로그인→로그인에도 유지됩니다. 종료 후 새 탭은 새 세션입니다. 사용자 수는 로그에 기록된 고유 계정이며 서버에서 인증한 사용자 수의 대체 지표가 아닙니다.
- 선택 기간 안에서 동일 세션이 지정 순서대로 도달한 단계만 집계합니다. 중복·재시도는 퍼널 세션 수를 늘리지 않습니다. 광고 면제와 인스타그램 사전 인증 같은 분기는 해당 퍼널을 거치지 않습니다.
- 알람: 홈→추가 클릭→입력 화면→등록 시도→등록 성공.
- 비로그인 전환: 소개 시트→로그인 CTA→로그인 실행→로그인 성공→입력 화면.
- 메시지: 메시지함→메시지 선택→열람 완료.
- 결제: 열람권 화면→구매 시작→SDK·서버 지급 완료→열람권 사용 완료. 이 정의는 2026-11-28 신규 빌드부터 적용되며, 이전 빌드는 추가된 단계가 없으므로 전체 흐름을 채우지 않습니다. 매출·정산은 서버 결제 내역으로 확인해야 합니다.
- 열람권 사용: 열람권 화면→사용 시도→열람 완료. 구매 없이 보유 열람권을 사용하는 경우도 포함합니다. 이미 열어본 메시지를 다시 보는 경우는 포함하지 않습니다.
- 반응: 메시지 열람→반응 시도→반응 완료. 신고: 신고 제출→완료. 실패 이벤트는 오류·취소 메뉴에서 확인합니다.
- `message_open_click`에는 잠김/재열람/무료 구분과 읽음 상태를 기록합니다. 받은 메시지의 보유 수량 노출(`message_wallet_view`), 상품 선택(`message_pass_product_select`)도 수집합니다. 메시지 ID·본문·인스타그램 ID·신고 사유·선택한 이모지는 전송하지 않습니다.
- 인스타그램: 코드 요청→코드 발급→인증 성공.
- 방문 추이는 KST 기준이며 빈 날짜도 0으로 표시합니다. 선택 기간은 최근 24시간/7·14·30일의 이동 구간입니다. 재방문율로 표시하지 않습니다.
- 분석은 선택 기간 최대 50,000건을 처리합니다. 초과 시 일부 데이터로 숫자를 만들지 않고 기간 축소 안내를 표시합니다.

## 수집 및 한계

이벤트는 최대 50건씩 전송하고 UUID를 DB id로 사용해 전송 재시도를 중복 제거합니다. 실패 시 5초 후 재전송하며 화면 숨김·종료 때 keepalive로 전송합니다. 메모리 버퍼는 최대 1,000건이며 앱 강제 종료, 광고 차단, 장시간 오프라인에는 누락될 수 있습니다. 내구성 있는 오프라인 저장은 하지 않습니다.

이벤트 파라미터는 허용된 분류·숫자·불리언만 저장합니다. 인스타그램 ID, 메시지 본문, 인증 코드, 자유 입력과 오류 원문은 저장·SDK 전송에서 제외합니다. 최근 행동 화면에도 세션·계정 식별자를 노출하지 않습니다. 브라우저 행동은 조작 가능하므로 권한 판단·정산 근거로 사용하지 않습니다.

수집 POST API는 익명 사용자를 지원하므로 공개되어 있습니다. 운영 인프라에서 요청 제한을 적용할 수 있으며, 입력 검증과 배치 크기 제한은 코드에 포함되어 있습니다. 기존 클라이언트의 UUID 없는 이벤트는 수집 시 UUID를 발급하므로 예전 클라이언트 재전송의 중복은 구분할 수 없습니다.

## 2026-11-28 화면 변경 반영

- 공통 X 닫기는 `sheet_close_click`, 나중에 하기는 `sheet_later_click`으로 기록하며 `source`로 시트를 구분합니다. 배경·뒤로가기 닫기는 이 클릭 이벤트에 포함하지 않습니다.
- 회원 탈퇴, 인스타그램 첫 인증 보상, 알람 등록 보상, 출석 보상 퍼널을 추가했습니다. 보상 처리 실패는 `rewards_claim_fail`, 받기 요청은 `rewards_claim_queue`로 구분합니다.
- 인증·알람 보상의 ‘처리 완료’에는 이미 지급된 요청의 정상 응답도 포함되므로 실제 신규 지급 수량은 서버 원장으로 확인합니다.
- 이 이벤트가 포함된 앱이 실제 출시되기 전에는 새 이벤트가 운영 데이터에 쌓이지 않습니다. 기존 이벤트와 API 방식은 유지합니다.
